# Diagram Extraction Feature Spec

## Overview

An optional post-notes step that lets users crop diagrams from their source PDFs and insert them contextually into the right topic in their study notes. Claude handles topic placement; the user handles selection. No server-side PDF rendering required.

## Design principles

- Notes are generated first — this is an enhancement layer, not part of the core flow
- User selects which diagrams to keep; Claude decides where they go
- Everything before the final API call happens in the browser — no infrastructure dependencies beyond what already exists
- Works in two sessions: immediately after upload (file in memory) or later (file fetched from Supabase source files)

---

## User flow

1. After notes are generated, an "Add diagrams" button appears (on the notes page, near "Add source")
2. Clicking it opens a full-screen or modal diagram tool
3. Claude pre-scans the PDF pages and identifies which ones contain diagrams worth keeping — only those pages are shown
4. User sees pages one at a time with a simple interface:
   - Draw a rectangle over the diagram they want
   - **Keep** — saves the crop and moves to next page
   - **Skip** — moves to next page without saving
5. For each kept diagram, it's sent to Claude with the full notes JSON — Claude returns the best-matching topic
6. A confirmation step shows the user where each diagram will be placed, with a dropdown override to move it to a different topic if Claude got it wrong
7. Diagrams are saved to Supabase and inserted into the notes

---

## Technical approach

### PDF rendering (client-side, no server needed)

- Use `pdf.js` — the same library browsers use natively
- Renders each PDF page directly onto an HTML `<canvas>` element
- No conversion step, no external service, no Vercel function involved
- Pre-render the next page in the background while user is deciding on the current one

### Crop tool

- User draws a bounding box with mouse/touch drag over the canvas
- On confirm, extract that canvas region using `canvas.toDataURL()` — produces a PNG
- ~200 lines of custom frontend code

### Two file sources

- **Same session as upload**: PDF is already in memory, pass directly to `pdf.js`
- **Later session**: fetch from Supabase source-files bucket via signed URL, then same flow

### Diagram page detection

- Send each page to Claude as a canvas-rendered image
- Ask only: "Does this page contain a diagram, chart, or labelled figure worth including in study notes? Yes or no."
- Only show pages where Claude says yes
- Filters out logos, decorative images, chapter headers, etc.

### Topic placement

- Send the cropped PNG + full notes JSON to a new API endpoint
- Claude returns the topic name it belongs to (easy classification — just the diagram, nothing else)
- User sees the match and can override via dropdown before confirming

## Schema changes

The notes JSON needs an optional `image` field on subtopics:

```json
{
  "name": "Cell Division",
  "points": ["..."],
  "image": {
    "url": "https://...supabase.../diagram-abc123.png",
    "caption": "Stages of mitosis"
  }
}
```

Caption is generated by Claude at placement time.

## Storage

- Cropped diagram PNGs stored in Supabase `source-files` bucket (or a new `diagrams` bucket)
- Path: `{userId}/{noteId}/diagrams/{timestamp}.png`
- Linked to the note record via the notes JSON

---

## Supabase config required

The source-files bucket needs CORS configured so `pdf.js` can fetch PDFs directly from the browser:

- **Allowed origins**: production domain + localhost for dev
- **Allowed methods**: `GET`
- **Allowed headers**: `*`

Alternatively: add a proxy endpoint (`/api/notes/[id]/source-files?action=proxy`) that streams the file through the server — avoids CORS config entirely and works everywhere including localhost.

---

## New API endpoints needed

- `POST /api/notes/[id]/diagram-scan` — takes a rendered page image, returns `{ hasDiagram: bool }`
- `POST /api/notes/[id]/diagram-place` — takes a cropped PNG + notes JSON, returns `{ topic: string, caption: string }`
- `POST /api/notes/[id]/diagram-save` — saves the final diagram placements to the note record

---

## What's not needed

- Server-side PDF rendering
- External PDF processing services
- New infrastructure beyond Supabase storage + three small API endpoints
- Any changes to the existing notes generation flow

---

## Open questions

- Should diagram capture be available immediately after notes are generated, or only accessible later via the source files panel?
- Should it support images uploaded as screenshots (not PDFs)? Probably not in v1 — screenshots are already single images and the user can see the whole thing.
- Mobile support: touch-based crop drawing is doable but needs separate attention.
